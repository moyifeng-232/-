# 校园二手交易平台模块实现文档

## 项目概况
校园二手交易平台是一个基于React+Spring Boot的全栈Web应用，用于校园内师生之间的二手商品交易。系统采用前后端分离架构，包含用户管理、商品管理、订单管理、统计分析等核心功能。

## 目录结构
```
校园二手交易平台-v2/
├── backend/           # 后端Spring Boot项目
├── frontend/          # 前端React项目
└── Info.txt           # 模块实现文档
```

## 1. 用户管理模块

### 1.1 功能描述
- 用户注册、登录、信息维护
- 管理员对用户信息的审核与管理
- 商家用户申请与审核

### 1.2 技术实现
**前端实现**：
- 注册页面：`pages/Register.js`
- 登录页面：`pages/Login.js`
- 个人中心：`pages/UserProfile.js`
- 管理员用户管理：`pages/AdminUserManagement.js`

**后端实现**：
- Controller：`UserController.java`
- Service：`UserService.java`、`UserServiceImpl.java`
- Mapper：`UserMapper.java`
- 实体类：`User.java`

### 1.3 核心流程
1. **用户注册**：
   - 前端验证表单数据
   - 调用后端API `/api/user/register`
   - 后端进行密码加密存储
   - 返回注册结果

2. **用户登录**：
   - 前端发送用户名和密码
   - 后端验证并生成JWT令牌
   - 前端存储令牌和用户信息到localStorage
   - 跳转到首页

3. **管理员审核**：
   - 管理员查看待审核用户列表
   - 审核通过/拒绝用户申请
   - 更新用户状态

### 1.4 关键代码
```java
// UserServiceImpl.java - 注册功能
public Result register(User user) {
    // 密码加密
    user.setPassword(passwordEncoder.encode(user.getPassword()));
    // 设置默认状态
    user.setStatus(1);
    // 保存用户
    boolean saveResult = save(user);
    if (saveResult) {
        return Result.success(null, "注册成功");
    } else {
        return Result.error("注册失败");
    }
}
```

## 5. 信誉评价模块

### 5.1 功能描述
- 交易完成后，双方进行互评
- 生成信誉度分数与评价记录

### 5.2 技术实现
**前端实现**：
- 购买记录页面：`pages/PurchaseHistory.js`（买家评价卖家）
- 已发布商品页面：`pages/PublishedProducts.js`（卖家评价买家）

**后端实现**：
- Controller：`OrderController.java`（新增 `/api/order/evaluate` 接口）
- Service：`OrderServiceImpl.java`（新增 `evaluateUser` 方法）

### 5.3 核心流程
1. **评价触发**：
   - 订单状态变为"已完成"
   - 双方可以互相评价

2. **评价操作**：
   - 点击"点赞"按钮
   - 显示确认弹窗
   - 确认后调用API `/api/order/evaluate`
   - 更新对方信誉值

3. **信誉值计算**：
   - 每次评价成功，对方信誉值+1
   - 信誉值存储在用户表的 `creditLevel` 字段

### 5.4 关键代码
```java
// OrderServiceImpl.java - 评价用户
public boolean evaluateUser(Long orderId, Long userId) {
    // 获取被评价用户
    User user = userService.getById(userId);
    if (user == null) {
        return false;
    }
    
    // 更新用户信誉值
    user.setCreditLevel(user.getCreditLevel() + 1);
    user.setUpdateTime(new Date());
    
    // 保存更新
    return userService.updateById(user);
}
```

## MVC架构设计

### 1. 架构概述
本项目采用前后端分离的MVC（Model-View-Controller）架构设计模式。前端采用React的MVVM（Model-View-ViewModel）架构，后端采用传统的MVC架构，通过RESTful API进行数据交互。

### 2. 前端MVVM架构

#### 2.1 各层职责

| 层       | 职责描述                                                                 | 实现文件/目录                          |
|---------|----------------------------------------------------------------------|-----------------------------------|
| **View** | 视图层，负责UI展示和用户交互                                                  | `pages/`目录下的所有页面组件，如`Login.js`、`ProductList.js`等 |
| **ViewModel** | 视图模型层，连接View和Model，处理数据绑定和业务逻辑                              | React组件的state和props，自定义Hooks       |
| **Model** | 模型层，负责数据管理和业务逻辑，包括API调用、数据处理等                                | `api/`目录下的API封装，如`userApi.js`、`productApi.js`等 |

#### 2.2 前端数据流
1. 用户在View层进行交互操作
2. ViewModel层接收用户操作，调用Model层获取数据
3. Model层通过API请求后端数据
4. 后端返回数据后，Model层处理数据并传递给ViewModel层
5. ViewModel层更新state，触发View层重新渲染

### 3. 后端MVC架构

#### 3.1 各层职责

| 层               | 职责描述                                                                 | 实现文件/目录                          |
|-----------------|----------------------------------------------------------------------|-----------------------------------|
| **Controller**  | 控制层，处理HTTP请求，接收和验证请求参数，调用Service层处理业务逻辑，返回响应结果             | `controller/`目录下的所有Controller类，如`UserController.java`、`ProductController.java`等 |
| **Service**     | 业务逻辑层，实现核心业务逻辑，调用Mapper层访问数据库，处理数据转换和业务规则                  | `service/`目录下的Service接口和实现类，如`UserService.java`、`UserServiceImpl.java`等 |
| **Mapper/DAO**  | 数据访问层，负责数据库操作，定义SQL语句或映射关系，封装数据库访问逻辑                          | `mapper/`目录下的Mapper接口和XML映射文件，如`UserMapper.java`、`OrderMapper.xml`等 |
| **Entity**      | 实体层，对应数据库表结构，封装数据模型                                               | `entity/`目录下的所有实体类，如`User.java`、`Product.java`等 |
| **DTO**         | 数据传输对象层，用于前后端数据交互，封装请求和响应数据，隔离内部实体结构                       | `dto/`目录下的DTO类，如`ProductDetailDto.java`、`PageResult.java`等 |

#### 3.2 后端请求处理流程
1. 前端发送HTTP请求到后端Controller层
2. Controller层接收请求，验证参数合法性
3. Controller层调用Service层的业务方法处理具体业务逻辑
4. Service层调用Mapper层访问数据库
5. Mapper层执行SQL语句，操作数据库
6. 数据库返回结果给Mapper层
7. Mapper层将结果转换为Entity对象返回给Service层
8. Service层处理业务逻辑，转换数据格式
9. Service层将处理结果返回给Controller层
10. Controller层将结果封装为统一响应格式，返回给前端

### 4. 前后端分离架构下的MVC协同
- **前端**：专注于用户界面和用户体验，通过API与后端交互
- **后端**：专注于业务逻辑和数据管理，提供RESTful API服务
- **数据交互**：采用JSON格式进行数据传输，实现前后端解耦
- **职责清晰**：各层职责明确，便于开发、测试和维护
- **可扩展性**：支持前后端独立开发、部署和扩展
